# VIC-28 — пользовательская доводка интерфейса

22 октября 2026 · Work S · отдельная ветка `dev/vic28-ui-s`. Нативные снимки сделаны 21 октября.

Это ограниченный polish-pass существующего Liquid Glass GUI после Preview 2 (`e51c71348102b05e1fa4005151b594c8919937a3`). Новые функции и интеграция в релиз не выполнялись. Иконка A, backend, DTO `vic28.dashboard/1`, authority-файлы, установщик, updater и штатный Tk GUI не менялись.

## Изменения

- Убраны внутренние обозначения VIC-28, Work S, read-only projection и технический ID рабочего пространства из обычной оболочки. Фактический ID, контракт, пути и ошибки доступны в диагностике. Именованное рабочее пространство показывается по текущему DTO; когда имя равно ID, используется нейтральное «Мои лекции».
- Для источника `kind=dev` постоянно виден индикатор «DEV · тестовая установка» и пояснение об изолированной тестовой установке. Синтетический пример обозначен отдельно.
- Основные вторичные подписи, статистика курсов и причины во «Входящих» увеличены до 12–13 CSS px, боковая панель немного расширена. Длинные русские и китайские названия, пути диагностики и подписи этапов переносятся. Прокрутка боковой панели сохранялась и до изменения; это проверено повторно, отдельного исправления не требовалось.
- Исправлено обрезание нижних этапов карточки при малой высоте окна: JS-граница снятия ограничения высоты приведена к существующему CSS breakpoint 700 px (ранее 650 px). При 1280×656 CSS px последняя строка карточки теперь доступна в естественной прокрутке.
- Пользовательские состояния упорядочены: «Сохранение расшифровки», «Расшифровка готова», «Ожидает ручной AI-обработки», «Проблема с материалами»; worker-подписи «Обработка лекций», «Диалоги», «Данные устарели», «Нет данных о работе», «Ошибка сигнала». ID статусов и причины backend сохранены. Отсутствие heartbeat не означает остановленный процесс.
- Неизвестные проценты, ETA и фактическое устройство остаются неизвестными; устаревшее наблюдение не превращается в текущий прогресс. Фильтры, поиск, карточки и диагностика продолжают использовать существующий снимок.

## Что работает и что не подключено

Работают обновление данных, навигация, поиск с сохранением IME-композиции, фильтры курса и этапа, выбор и прокрутка карточки, просмотр причин/Raw-presence/read audit, локальное уменьшение прозрачности. «О классическом интерфейсе» открывает информацию о сохранённом Tk GUI; запуск программы из веб-интерфейса не подключён.

Управление workers, приём записей, AI import/export, редактирование настроек, открытие файлов и updater остаются неподключёнными, как в Preview 2. Процент 57%, 2/3 и ETA в синтетическом примере — только явно обозначенная фикстура.

## Повторный запуск

Из корня UI-worktree, используя уже существующий Python:

```powershell
.\src\gui_web\Start-Dashboard.ps1 -DevRoot 'C:\PipLine GPT WORK\unified-dev' -Python 'C:\PipLine GPT WORK\app\runtime\document\python.exe' -Port 8898
.\src\gui_web\Start-Dashboard.ps1 -VisualFixture -FixtureRoot '.\.local\user-facing-polish\fixtures\normal' -Python 'C:\PipLine GPT WORK\app\runtime\document\python.exe' -Port 8899
```

Это два раздельных viewer; если порт уже занят оставленным демонстрационным viewer, откройте соответствующий локальный URL. Никакие workers не запускаются. Для QA сценариев используйте `-FixtureScenario stale|unknown|preparing` с отдельным `-FixtureRoot` и портами 8901–8903. Копия DEV Raw/SRT уже находится в `.local/vic28-dev-copy`, viewer 8900; исходные данные повторно не копировались.

В браузерных тестах задайте `NODE_PATH` на существующий Playwright в QA-окружении и, при необходимости, `CHROME_PATH`. Тестам нужны указанные viewer; это не зависимости приложения:

```powershell
$env:VIC28_DEV_URL='http://127.0.0.1:8898'
$env:VIC28_FIXTURE_URL='http://127.0.0.1:8899'
$env:VIC28_COPY_URL='http://127.0.0.1:8900'
$env:VIC28_STALE_URL='http://127.0.0.1:8901'
$env:VIC28_UNKNOWN_URL='http://127.0.0.1:8902'
$env:VIC28_PREPARING_URL='http://127.0.0.1:8903'
node tests\vic28_browser.cjs
node tests\vic28_preview2.cjs
node tests\vic28_polish.cjs
```

Для стандартного нативного gate используется прежний `src/gui_web/Start-NativeGate.ps1 -Url 'http://127.0.0.1:8898'` с существующими SDK DLL и runtime. В этом проходе отдельное тестовое окно собрано в `.local/user-facing-polish/native/bin/PolishGate.exe`. EXE/DLL/profile не включаются в исходники и не становятся архитектурной зависимостью продукта.
